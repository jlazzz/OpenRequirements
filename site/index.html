Requirements management you can host yourself

Write requirements, trace them to the tests that verify them, freeze baselines, get reviews signed, and run the tests. One open-source tool, one Docker Compose file, your own server.

Everything a regulated team needs to show its work

Built for hardware, medical, aerospace and software teams who have to prove that what they built is what they said they would build.

Versioned items

Every save is a new version. History is append-only and nothing is ever hard-deleted.

Traceability

Typed relationships, a traceability matrix, trace views and impact analysis in both directions.

Suspect links

When one end of a relationship changes, the other end is flagged until someone confirms it still holds.

Baselines

Name an immutable snapshot, compare it with now or with another baseline.

Reviews and signatures

Reviewers mark items, approvers sign with their password. Closed reviews download as Word.

Test management

Plans, cycles, step-by-step runs with evidence, and results that roll up into each requirement.

Import and export

ReqIF, Word, CSV and spreadsheets in; ReqIF, Word, CSV and a JSON backup out.

API first

The web app uses the same documented API as your scripts: OpenAPI 3.1, tokens, signed webhooks.

Edit like a document, store like a database

Each requirement has a stable ID, a rich-text description with tables, images and equations, and typed fields. Edits auto-save to a private draft until you press Save version.

  • IDs like SYS-042 are never reused
  • Two people editing? A merge screen resolves it field by field
  • Verification status shown beside every requirement

See what depends on what

Relationships are typed and directional. Coverage gaps and the cost of a change are computed live, never stale.

Traceability matrix between any two sets, with verification status on every row and column.

Trace view: pick how many levels up and down, and see which requirements reach a test.

Changes don’t slip through

Change a requirement and every relationship touching it becomes suspect. Open the changed item, compare versions, and confirm the link or fix what it points to.

  • Results go out of date when a test or requirement is revised
  • People involved are notified in the app, and by email if they choose

Run the tests, keep the evidence

Test plans select cases, cycles freeze their versions, and runs are executed step by step with the keyboard. Finishing a run records a result, and the requirement’s status follows.

Automated results come in as JUnit XML from CI and land on the same requirements. A failed test links to a defect in your own tracker. This is not a bug tracker, and does not try to be.

Baselines and signed reviews

Freeze a design review as a baseline. Reviewers mark items, approvers sign with their password, and the signed record is kept with a digest of what was approved.

  • Compare a baseline with the current state or another baseline
  • Frozen verification status, so a release shows what was proven at the time
  • Hash-chained audit log that can be anchored and verified

A baseline: every item as it was, with its verification status at the time.

Fits into the tools you already use

Coming from DOORS, Polarion or Jama?

Import ReqIF, Word and spreadsheets. Re-import updates items by ID instead of duplicating them.

CI

Upload JUnit results; a scanner for @req SYS-042 tags links code to requirements.

Jira, GitHub, GitLab

Attach issues and pull requests to items and see whether they are open or closed.

Sign-in

Local accounts, or OpenID Connect with your identity provider. Optional lockout and password expiry.

Your server, your data

One app image plus PostgreSQL. No telemetry, no accounts with us, no per-seat price. HTTPS through Caddy is one setting.

git clone https://github.com/jlazzz/OpenRequirements.git
cd OpenRequirements
docker compose -f deploy/docker-compose.yml up -d --build

Open http://localhost:3000. The first visit creates the administrator account. A demo project like the one in these screenshots loads with npm run demo.
